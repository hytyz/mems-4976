1. Overview

An ASP.NET Core MVC (.NET 10) application backed by EF Core Code First and SQLite, with ASP.NET Core Identity for administrators. Visitors browse municipalities and candidates, compare candidates and build a session-based personal voting guide that can be printed or exported to PDF. Administrators manage municipalities, positions, candidates and administrator accounts in the Admin area.

AreaImplementation
DatabaseEF Core Code First models and migrations (Data/Migrations). The connection string is read from ConnectionStrings:DefaultConnection in configuration; the application refuses to start without it. Every seeded municipality has positions and candidates.
AuthenticationASP.NET Core Identity with username/password login. There is no self-registration: only the Login, Logout and Access Denied pages exist, and accounts are created by a SuperAdmin.
AuthorizationSuperAdmin plus one distinct admin group (Identity role) per municipality, e.g. Pitt Meadows Admin. Members of a municipality group see and manage only that municipality.
Voting guideVisitors only. One municipality per guide and, for each position, no more candidates than there are seats.
UploadsImages are validated by extension, size and actual file content (file signature), renamed by the server and stored outside wwwroot, so a redeployment does not delete them.
Bonus featuresEndorsements, social/video links, dark mode, pagination, candidate comparison, PDF export.

2. Entity relationship diagram

  • A Municipality has many Positions, a Position has many Candidates, and a Candidate has many Endorsements. All three relationships cascade on delete.
  • Municipality.Name and Municipality.AdminRoleName are unique.
  • Each municipality owns one Identity role, named in AdminRoleName. Membership in that role (AspNetUserRoles) is what makes a user an administrator of that municipality. The role is created, renamed and deleted together with its municipality.
  • ApplicationUser extends IdentityUser.

4. Personal voting guide

The guide is stored in the visitor's session. It follows the rules of a real ballot: a guide covers a single municipality, and for each position a visitor can choose at most as many candidates as there are seats (one mayor, six councillors, and so on). The rules are enforced on the server in VotingGuideService.

7. Configuration

SettingPurpose
ConnectionStrings:DefaultConnectionSQLite connection string. Required. Defined in appsettings.json; override per environment with appsettings.Development.json or the ConnectionStrings__DefaultConnection environment variable / Azure App Setting.
Storage:UploadsPathFolder for uploaded images. When empty, the application uses %HOME%/data/uploads on Azure App Service (persists across deployments) and App_Data/uploads locally.

Running locally

cd src/MunicipalElections
dotnet run

The database is created, migrated and seeded on first start.

8. Azure deployment

The application is deployed to Azure App Service at https://mems-assignment-app.azurewebsites.net.

dotnet publish src/MunicipalElections -c Release -o publish
cd publish && zip -r ../app.zip . && cd ..
az webapp deploy --resource-group <resource-group> --name mems-assignment-app --src-path app.zip --type zip

Recommended App Settings so data survives redeployments:

ConnectionStrings__DefaultConnection = Data Source=/home/data/municipal-elections.db   (Linux)
ConnectionStrings__DefaultConnection = Data Source=C:\home\data\municipal-elections.db  (Windows)
